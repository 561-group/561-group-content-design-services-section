1. Read the actual consumer frontier and corresponding authority/rights/effective demand. Check reuse, receiver readiness, named destination, held provider allocations and known source/visual constraints. Do not mint needs to use available image allowances. A hypothetical scene is not a production purchase order.
2. Choose at most one admissible image with enough remaining wanted quantity and a concrete use; obtain the existing allocation/hold where the connected receiver legitimately exposes it. 3. Native ChatGPT ImageGen returns the new binary as a `file_...` source file reference. For its actual returned ID, the *interactively verified* handoff is:
   ```js
   await tools.files__manage_library({
     operations: [{
       operation: "upload",
       source_file_ref: { file_id: ACTUAL_IMAGE_FILE_ID },
       destination_path:
         "/Google Drive/561 Group/Media/ChatGPT-Web Image Generation — Ingress/" +
         UNIQUE_NONCOLLIDING_FILENAME
     }]
   });
   ```
   This example is a tool-shape contract, not a copy-pastable source for a scheduler without the real returned file ID. If only a real mounted file path is available, `container_path` is the supported alternative. **Do not** pass a `file_...` ID as the `file_uri` parameter of `Google_Drive__upload_file`: they are distinct file-reference carriers.
4. Obtain the actual Drive file ID from the successful upload result, then read `Google_Drive__get_file_metadata` and verify exact MIME, parent folder ID `1aHlPwb6XLx71n11_rCW8IWyaowfyqOb8` and file identity. Keep source binary and rights/provenance. A successful Library operation and independent Drive readback were both observed in an interactive run; **neither proves the multi-call unattended scheduler works**.
5. Evaluate actual bytes/contents against the brief. Mark a failed render as nonproduction/rejected. Only the named consumer may approve the generated candidate, compose/publicize it, and record later public-use/performance effects.

Use existing allocation event states `held → generated → delivered → public-use` or `released/refused`. **Drive-ingested** is a distinct custody fact, not synonymous with journal `delivered`, accepted or published. If an actual scheduled run cannot take the second tool action, report `GENERATED_NOT_IN_DRIVE` with the real recoverable source ID and the refused layer. If no eligible demand/tool exists, report `NOT_GENERATED` and the discriminating evidence. Do not send external correspondence, pay providers or publish.
