# Derive, fabricate, and receive a branded artifact

This procedure answers a specific repeated production job: **a real customer or
enterprise wants a page, asset, book, report, storefront, or other artifact that
remains recognizable as the correct brand while meeting the reader's actual
needs.** It is a use-and-improve *design procedure inside the original 561 Group
content-design corpus*, not a second brand registry, source of graphics, Work
queue, renderer, or license to overwrite a consumer's own voice.

Select it through original Work and the existing Coesite
[improve-research-technology-practice operation](https://github.com/coesite-operations/operations-services-section/pull/352)
and [Meet-then-Beat method](https://github.com/coesite-operations/operations-services-section/blob/main/lib/agency/skills/meet-then-beat/SKILL.md).
The current original design source is this corpus's
[Design Bible v0.3](../561-group-design-bible.md) and
[DTCG 2025.10 tokens](../../../../../data/records/design-tokens/561-group.tokens.json).
The illustrated Drive **v0.4 candidate** provides research and design evidence,
not an automatically adopted new edition.

## One source-qualified commissioning tuple

Recover, rather than invent, these inputs from the original Work, actual
consumer and competent rights holder:

| Name | Required reading | Refusal case |
| --- | --- | --- |
| Receiving job | The person or agent and action that the finished artifact makes easier | "Make it look prestigious" without audience/job |
| Source and voice | Brand owner, active edition/revision, voice and forbidden claims | A visual theme treated as authority to make sociopolitical or commercial claims |
| Material | Format/viewport/medium, figure(s), photographs, permissions, provenance, source data | Borrowed images or paid assets without a verified right |
| External baseline | Current alternative serving **the same reader job**, exact version/context, positive and negative user evidence | A style adjective offered as proof of competitor parity |
| Conformance | Versioned standard/profile and bounded measurable acceptance tests | A generic "passes WCAG" badge with no actual audit |
| Receiving | Competent independent recipient, evidence format, actual version, correction path | The builder checking "approved" on their own source PR |

Different clients may select different brands. **The Group's v0.3
tokens must never be imposed on an external customer's requested identity.**
A consented client identity and its applicable rules are parameters; where
absent, offer a clearly labeled proposal rather than fabricate approval.

## Research gesture — derive requirements from the job, not vibes

1. Read the originating request, existing illustrations and relevant comments
   before editing. Compare *what the user liked* to *what the user disliked*.
   A disliked page's copy can be replaced while its successful composition
   survives. Source examples are evidence of intent, not automatic deployment
   rights or a reason to publish personal artwork.
2. Recover current work from [the Content Design corpus](../561-group-design-bible.md),
   original Group brand tokens and relevant operations, web or print producers.
   Recover upstream standards and actual consumer capabilities at their **named
   versions**. For this kind of work the comparators include the
   [DTCG 2025.10 Format Module](https://www.w3.org/community/reports/design-tokens/CG-FINAL-format-20251028/),
   [WCAG 2.2](https://www.w3.org/TR/WCAG22/), and the actual requirements of
   the target medium. DTCG is a W3C *Community Group* report, not a W3C
   Recommendation.
3. For matched industry competitors, separate jobs: **Style Dictionary**
   translates token sets to platform artifacts; **Storybook/Chromatic**
   supports component visual snapshots and reviewed baselines; **Playwright**
   exercises a real browser page. Do not claim the Group has met, much less
   beaten, an entire product by parsing a token file. Establish comparable
   inputs, output surfaces, time/energy/compute costs where measured, refusal
   behavior, independent practical acceptance and repeatability.
4. Translate evidence into separately checkable requirement statements:
   readable task, authentic voice, correct type hierarchy, token/geometry
   conformance, accessibility, source attribution, useful actions, lawful
   ownership, visual acceptance. A hypothesis or a preference should remain
   labeled as such.

**Research output:** a source-qualified set of requirements and falsifiers
linked to the existing Work. A mood board and a scientific paper are not
interchangeable. Research must not imply that a hypothesized philosophical
distinction is proved simply because it has a striking poster.

## Technology gesture — repair the original makers

5. Choose the existing producer: Group Content Design owns the visual language
   and DTCG tokens; Red Cup Web Theming translates reusable token/contrast
   contracts; TUFTE and the authorized site application compose real pages;
   Red Cup Visual Asset Generation composes separately licensed assets. Reuse
   the closest admitted template per [Template fork](template-fork.md).
   If source, package export, renderer, asset storage or operations reader is
   missing, repair *that seam*, not a new independent CSS copy.
6. Keep values in the source-owned token profile. Derive CSS, printable rules
   and other medium outputs from the same approved inputs. Preserve the house's
   three type channels, geometric grids, named color roles, restrained accents,
   numbered folio, semantic captions and original client context.
   Automatically generated images never themselves certify source, licensing
   or author approval.
7. Exercise positive and **adverse** conformance tests. A brand-critical
   change must fail if the colors mutate, the typography is replaced by system
   fonts, a numbered mark vanishes, the layout clips at a supported viewport,
   a page introduces an identity-led claim that its owner rejected, a figure
   loses provenance, or keyboard readers cannot see focus.
8. Make a *real rendered artifact* with the original engine, at least one
   desktop and one phone viewport when the output is web, and a relevant print
   specimen when print is an actual target. Retain dated screenshots or
   print proofs, source commit, fonts, named media modes, and configuration
   versions. A CSS string test is not proof of computed browser style.
   Screenshots without a separately approved golden reference are
   **candidate evidence**, not automatically accepted or rejected diffs.

For the Group use [Color-budget application](color-budget-application.md):
alarm-red bounding-box coverage at most 6%, witness-blue at most 3%.
Text color contrast and link discernibility are separate requirements.
Do **not** print red text on bone at body size merely because the mark uses
red; the Design Bible identifies that contrast failure.

## Practice gesture — independent receiving, then improve the producer

9. Deliver the exact edition, output, evidence and a legible review packet
   through the original Work/receiving lane. The reviewer should see the
   artifact *before* reading its internal issue. Ask whether (a) the intended
   job is clear, (b) the visual feels continuous with the approved reference,
   (c) the content makes no unsupported identity/performance claim,
   (d) focus/motion/zoom work, and (e) any expressive departure is intentional.
   An assayer must be separate from the builder when independent acceptance
   is required.
10. Record accepted, rejected, contested or *not yet independently observed*
    against the specific tested artifact and source revision. A merged PR,
    passing code test, successful Cloudflare deploy, or screenshot archive
    proves only its own bounded stage. Do not relabel it as buyer approval.
11. For an accepted variation, retain the exact applicable client/surface.
    Promote a truly reusable template only through the
    [three-independent-uses rule](template-fork.md). When a real counterexample
    exposes a flaw in this procedure, edit the original source and **use the
    repaired method on the next authorized Work**, measuring whether rework
    or the recipient's rejection actually decreases.

## Observed first case: the 561.group homepage, 2026-10-22/23

**Original intent:** new ecological/economic/relational public content while
preserving the established Bauhaus/brutalist visual language. The Live
homepage initially reintroduced a "Lakota-founded" sales appeal and
discarded the owner's existing design language. A good CSS render and a
source-to-Cloudflare receipt were not enough to detect that violation.

- [Site correction #33](https://github.com/561-group/561.group/pull/33)
  restored the original house look and replaced unwanted hero text.
- [Content Design source repair #1](https://github.com/561-group/561-group-content-design-services-section/pull/1)
  fixed the real DTCG paths and added typed negative tests.
- [Web Theming source repair #1](https://github.com/red-cup-engineering/web-theming-service/pull/1)
  strengthened reusable typed token ingress.
- [Site source→renderer receiving #36](https://github.com/561-group/561.group/pull/36)
  now checks the site's actual TUFTE consumer against a pinned Group design source.
- [Site rendered-browser assay #37](https://github.com/561-group/561.group/pull/37)
  proposes computed styles and bounded screenshot review artifacts from
  the actual application. Its source and CI state must be read at use time;
  the existence of a PR **does not** assert browser acceptance or human
  review of pixels.

**Failed earlier tactic:** producing more promotional copy and validating
specific phrases in tests while neglecting recovered design standards.
**Changed method:** qualify source **and** real rendered page against
original identity and practical reader outcomes, then seek independent
visual acceptance. That combination—not a name like "brand engine"—is
the measurable improvement claim to test.

This method currently remains a **candidate** until its own source review
and at least one actual consumer reception. Do not upgrade frontmatter
status merely because this text was committed.
